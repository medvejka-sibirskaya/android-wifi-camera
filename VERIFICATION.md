# Звук и запись · Android 0.3.0 / Windows 0.4.0

13 ноября 2026 года. Доработка по отдельному поручению пользователя в чате портфолио.

- Добавлен микрофон Android с RECORD_AUDIO и явным включением; PCM16 mono 16 кГц,
  отдельные HTTP-запросы с кодом, IP-привязкой и идентификатором медиасессии.
- Прослушивание в Windows-панели через Web Audio API по кнопке «Слушать».
- Локальная запись AVI: MJPEG 1280×720, 10 кадров/с + PCM16. Без новых runtime
  зависимостей; до 1 ГиБ на файл, явный старт/стоп и завершение после потери видео.
- 19 тестов Python прошли, включая независимое декодирование видео/аудио PyAV,
  запрет записи без явного локального действия, границы буферов, короткие записи
  и сохранение хвоста. PyAV установлен только в work/av-verification.
- Chromium: получение PCM и планирование в реальном AudioContext, включение/выключение
  прослушивания, начало/конец реальной записи, статус, темы, снимки, потеря/возврат,
  узкое окно и завершение — пройдены. Прослушивание тестировалось с mute-audio:
  это проверка программного воспроизведения, не субъективная оценка наушников.
- assembleDebug + lintDebug успешны; 0 ошибок, 5 предупреждений.
- После обновления повторно проверен прямой видеовыход: DirectShow 24 живых кадра
  1280×720; Chrome WebRTC получил изменяющиеся кадры 1280×720. Отчёты обновлены.
- APK обновлён на тестовом Android-устройстве. Получены реальные PCM. AVI с телефона независимо декодирован: 30 кадров 1280×720,
  48000 семплов, 3 секунды; длительности дорожек совпали. Проверены микрофон
  выключен по умолчанию, mute без остановки видео, повторное включение, остановка
  и видео, и микрофона в фоне. Отчёт: audio-device-test.json. Тестовая запись удалена.
- Независимое ревью нашло и помогло исправить обрезку хвоста/пустую короткую запись
  и привязку аудиометок к моменту read. Теперь AudioTimestamp BOOTTIME + sample count.

Не подтверждены: длительная запись, достижение 1 ГиБ в аппаратном прогоне,
субъективная синхронизация губ/звука, задержка и качество звука в разных условиях,
другие телефоны/компьютеры и восстановление файла после аварийного отключения питания.
Виртуальный микрофон Windows не добавлялся: пользователь сохраняет наушники в Zoom.
Прямой видеовыход и предыдущие проверки описаны ниже; исторические версии не путать
с текущими номерами.

# Прямая камера Windows · приёмник 0.3.0

13 ноября 2026 года. Проверка на Windows x64.

## Подтверждено

- MIT-фильтр Unity Capture из закреплённого commit зарегистрирован как
  Wi-Fi Camera для 32- и 64-битных приложений. DLL проверены SHA256,
  хранятся рядом с приёмником; OBS/iVCam не изменялись.
- Приёмник 0.3.0 получает кадры тестового Android-устройства и напрямую пишет в компонент.
- DirectShow: устройство перечисляется и открывается, получены 23 кадра 1280×720.
  Отчёт native-camera-test.json. Сначала OpenCV по индексу не открыл устройство;
  штатный DirectShow-граф через pygrabber успешно выполнил захват.
- Chrome WebRTC: выбрана именно Wi-Fi Camera, getUserMedia получил 1280×720,
  непустые и изменяющиеся кадры. Отчёт browser-camera-test.json.
- Пользователь подтвердил живую картинку в Zoom после полного закрытия OBS.
- 12 проверок приёмника прошли. Исправлен TCP-reset при отклонении запроса
  с фиксированной длиной и запрещённым Transfer-Encoding/типом: тело ограниченно
  считывается перед отказом; такие запросы по-прежнему не принимаются.
- Проверка панели Chromium прошла: темы, ожидание, JPEG, снимок, потеря/возврат,
  узкое окно, завершение. Инструкция и кнопка теперь относятся к Wi-Fi Camera.
- Камера не записывалась на диск; только числовые показатели и тестовые изображения.

## Не подтверждено

Другие компьютеры, 32-битный захват (регистрация проверена), Windows Camera/UWP,
абсолютно все конференц-приложения, несколько потребителей одновременно,
длительный прогон и измерение задержки. Браузерный тест выполнен локально,
без отправки изображения на сервис конференций. Оконный инструмент недоступен:
Zoom проверен пользователем, а не автоматическим управлением его интерфейсом.

Предыдущие проверки Android 0.2.0 сохраняются ниже.

# Проверка версии 0.2.0

13 ноября 2026 года.

APK установлен на тестовое Android-устройство. Проверка предыдущей сборки: assembleDebug и lintDebug успешны, 0 ошибок и 5 предупреждений (обновления зависимостей и fullSensor).

Пользователь подтвердил автоповорот и переключение полного экрана касанием в горизонтальном положении. Финальная сборка распространяет тот же жест на вертикальное положение и установлена. Повторная проверка на подключённом телефоне подтвердила скрытие и возврат панелей; телефон при проверке был горизонтально. Полный экран сохраняется при смене ориентации. Удержание пальца — фокус, два пальца — масштаб. Отдельной кнопки нет.

Все 12 проверок приёмника прошли, включая штатную проверку страницы OBS через Node. Проверка панели Windows в Chromium прошла: темы, кадр, снимок, потеря и восстановление связи, узкое окно, остановка приёмника и отдельная страница OBS. Петролевые цвета применены к обоим интерфейсам.

Аппаратный прогон подтвердил кадры 720×1280 и 1080×1920, переключение камер, фонарь, зеркало, переподключение и остановку передачи в фоне: ui-device-test.json. Камера на диск не записывалась.

Не подтверждены: фактический вывод OBS Virtual Camera в видеосвязь, длительный прогон, измерение задержки, качество фокусировки и масштаба, другие телефоны. Использованы официальные референсы iVCam, окно установленной программы инструментом не просмотрено.

HTTP только для доверенной локальной сети, без шифрования. Четыре цифры, блокировка на минуту после пяти ошибок, привязка первого отправителя по IP. APK отладочный; для поставки нужен постоянный ключ подписи поставщика.
